# Product Principles

Version: 1.0

---

# Purpose

These principles define how Freedom Planner should make product decisions.

Every feature, calculation, screen and interaction should align with these principles.

If a feature conflicts with one or more principles, it should be reconsidered before implementation.

---

# Principle 1
## Freedom Over Wealth

Freedom Planner does not exist to maximise net worth.

It exists to maximise lifetime freedom.

Money is simply a tool that buys choices.

The application's success is measured by increasing the user's ability to decide:

- when to work
- how much to work
- whether to work at all

---

# Principle 2
## Decision Support Over Bookkeeping

Freedom Planner is not budgeting software.

It is not accounting software.

It does not aim to replace banking apps.

Instead it should answer questions such as:

- Am I on track?
- What should I do next?
- Can I afford this?
- What is the opportunity cost?
- How does this affect my Freedom Date?

---

# Principle 3
## Simple Inputs
### Powerful Outputs

The user should only enter information that genuinely improves calculations.

Avoid asking for unnecessary information.

The application should derive as much information as possible from a small number of inputs.

---

# Principle 4
## Dashboard First

The dashboard is the most important screen.

Within ten seconds the user should understand:

- Am I on track?
- What changed?
- What should I think about?
- What's my next milestone?

If these questions are not answered, the dashboard has failed.

---

# Principle 5
## Life Comes Before Optimisation

Freedom Planner should never encourage the user to sacrifice all enjoyment today in pursuit of tomorrow.

Holidays.

Meals out.

Experiences.

Family.

These are goals of financial planning, not obstacles to it.

---

# Principle 6
## Every Feature Must Earn Its Place

Before adding a feature ask:

Does this help make better financial decisions?

If the answer is no...

It belongs in the backlog.

---

# Principle 7
## Manual Is Acceptable

Version 1 is designed for one user.

Manual data entry is acceptable.

Automation is desirable but never required.

Accuracy is more important than convenience.

---

# Principle 8
## Progressive Complexity

The application should feel simple.

Advanced functionality should reveal itself naturally.

New users should never feel overwhelmed.

---

# Principle 9
## Explain Every Recommendation

Whenever the application recommends an action it should explain why.

Example:

Investing £300/month is expected to increase your Freedom Date by approximately 14 months compared with overpaying your mortgage.

Users should understand recommendations rather than blindly follow them.

---

# Principle 10
## Celebrate Progress

Freedom Planner should be motivating.

Achievements matter.

Milestones matter.

The Freedom Ladder exists because progress is easier to understand than numbers.

The application should celebrate meaningful achievements.

---

# Guiding Question

Every design decision should answer:

"Will Future Me thank Present Me for this?"
